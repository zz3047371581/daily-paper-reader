## 摘要
流式视频理解要求模型在未来问题未知之前持续保留有用的视觉证据。现有方法主要根据标记重要性、时间冗余或片段级相关性管理不断增长的视觉上下文，但很少围绕随时间持续存在和演变的对象来组织证据。因此，在本文中，我们提出了ObjectStream，一个无需训练的框架，它将潜在对象视为流式视频理解的记忆锚点。ObjectStream直接从冻结的视频大语言模型表征中诱导空间一致的潜在对象，跨帧将它们链接为持久锚点，并在有限的内存预算下维护其历史记录，无需外部对象检测器或分割模型。基于这些锚点，ObjectStream保留了三种互补的证据形式：持久对象历史、瞬态对象变化和近期视觉上下文。这种设计使现有的视频大语言模型能够推理对象的身份、交互和状态变化，同时保持底层模型不变。在在线流式和离线长视频基准上的大量实验证明了其有效性和效率。在在线流式评估中，ObjectStream在OVO-Bench实时视觉感知上将Qwen2.5-VL-7B提升了10.0个百分点，同时将峰值GPU内存和TTFT降低了约50%。在离线长视频基准上，它超越了全标记基线，同时丢弃了82.5%的视觉标记。这些结果凸显了潜在对象作为紧凑流式视频记忆的实际且有效的组织原则。

## Abstract
Streaming video understanding requires models to continuously retain useful visual evidence before future questions are known. Existing approaches primarily manage the growing visual context according to token importance, temporal redundancy, or segment-level relevance, but rarely organize evidence around objects that persist and evolve over time. Thus, in this paper, we introduce ObjectStream, a training-free framework that treats latent objects as memory anchors for streaming video understanding. ObjectStream induces spatially coherent latent objects directly from frozen Video-LLM representations, links them across frames into persistent anchors, and maintains their histories under a bounded memory budget, without requiring external object detectors or segmentation models. Built on these anchors, ObjectStream preserves three complementary forms of evidence: persistent object histories, transient object changes, and recent visual context. This design enables existing Video Large Language Models (Video-LLMs) to reason over object identities, interactions, and state changes while leaving the underlying model unchanged. Extensive experiments on online streaming and offline long-video benchmarks demonstrate both effectiveness and efficiency. In online streaming evaluation, ObjectStream improves Qwen2.5-VL-7B by 10.0 points on OVO-Bench Real-Time Visual Perception, while reducing peak GPU mem-ory and TTFT by approximately 50%. On offline long-video benchmarks, it surpasses the full-token baseline while discarding 82.5% of visual tokens. These results highlight latent objects as a practical and effective organizing principle for compact streaming video memory.

- **整体含义**：提出一种**无训练、即插即用的对象中心视觉记忆框架**，将潜在于 Video-LLM 表征中的“潜在对象”作为记忆锚点，在严格的内存和延迟约束下，为流式视频推理提供紧凑、对象级的时空证据。

## 2. 方法论：核心思想、技术细节与流程
### 核心思想
- 不依赖外部检测器或分割模型，直接从冻结的 Video-LLM 视觉 token 中**诱导出空间连贯的潜在对象**，跨帧建立持久关联，并以有限内存维护其演化历史，从而构造对象锚定的长期记忆。

### 三大记忆模块
1. **潜在对象锚定记忆 (Latent Object-Anchored Memory, LOAM)**
   - **S1 查询无关的 Token 显著性估计**：对每帧视觉 token 归一化，聚合为全局上下文向量，通过余弦不相似度计算每个 token 的显著性分数，并使用分位数阈值选取活跃候选 token。
   - **S2 空间聚类发现潜在对象**：利用 2D Patch 网格结构，将空间相邻的活跃 token 通过连通分量聚类，形成帧级候选对象，并以显著性加权的方式归一化获得对象特征。
   - **S3 跨帧关联与有界对象集维护**：维护一个包含对象特征、时间戳、时间一致性分数和显著性分数的动态对象集。对新候选对象，通过余弦相似度与已有对象匹配（EMA 更新），不满足阈值则新建对象；当对象数量超出预算 M 时，按“**最近性、显著性、时间一致性**”字典序排名淘汰低优先级对象。
   - **S4 对象中心证据保留**：在每个被保留的对象轨迹内部，按显著性分数选取 Top-K 个历史 token，最终拼接为长期对象记忆 $R_{\tau}^{\text{object}}$。

2. **对象条件时序残差 (Object-Conditioned Temporal Residuals, OCTR)**
   - 针对平滑处理可能掩盖的**短期突变**（如动作转换、状态变化），对每个对象轨迹的相邻观测计算特征变化 $\Delta$，采用自适应阈值 $\gamma$（均值和标准差之和）检测时间事件，并在事件时刻附近的局部时间窗口内选取高显著性 token，作为补充的瞬态残差记忆 $R_{\tau}^{\text{temporal}}$。

3. **近期视觉接地区 (Recent Visual Grounding Window, RVGW)**
   - 直接保留最近 $L$ 帧的原始视觉 token $R_{\tau}^{\text{rvgw}}$，为实时问答提供高保真的当前视觉状态。

- **推理时**，语言模型以拼接后的记忆 $R_\tau = R_{\tau}^{\text{object}} \cup R_{\tau}^{\text{temporal}} \cup R_{\tau}^{\text{rvgw}}$ 为条件生成答案。

## 7. 优点
- **完全无训练、即插即用**：不修改底层 Video-LLM，无需额外检测器或分割器，易于集成。
- **对象中心记忆组织**：以自然语义单元组织历史证据，相比 token 级或片段级压缩，能更好地保留对象身份和状态变迁。
- **三重记忆互补**：长期对象平滑历史 + 瞬态残差 + 近期窗口，覆盖多重时间粒度需求。
- **高效且可扩展**：在严苛内存和延迟限制下，性能提升显著，且观察到在不同模型规模（3B/7B）下一致有效。

## 8. 不足与局限
- **对象发现的鲁棒性**：潜在对象完全从冻结的 Video-LLM 表征中挖掘，其空间聚类和跨帧关联效果**依赖原始视觉编码质量**，在面对小物体、严重遮挡或视角剧烈变化时可能出现断裂或丢失。
- **阈值的敏感性**：多个超参数（显著性分位数 q、匹配阈值 θ、对象预算 M、时间窗口大小等）需按任务场景调试，可能不具备统一的即装即用最优设定。
- **长视觉流的上限**：尽管在 1024 帧以内的长视频基准中表现良好，但对象痕迹的长期累积和内存预算约束在真正的无限长流式场景中依然面临挑战，论文未进一步探索极限情形下的记忆衰退。
- **外部模型对比的缺失**：虽然对比了 SAM+DINOv2 分割方式，但未详细讨论如何将其输出的分割掩码更好地融入流式记忆，仅指出其代价过高，没有尝试混合策略（如轻量级检测器辅助）以进一步提升对象发现精度。
- **实验覆盖**：评估集中于开源骨干 Qwen2.5-VL，对其他主流 Video-LLM 的兼容性测试尚缺；且在线基准视频大多为 1 fps 采样，实时性验证可能未覆盖更高帧率输入。
